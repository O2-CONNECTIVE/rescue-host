# デザインとアクセシビリティの確認方法

[基準案へ戻る](design-accessibility.md) / [既存の表示検証](tauri-design-verification.md) / [CI の範囲](ci.md)

自動検査は見落としを減らす補助であり、操作と支援技術の確認を置き換えません。
以下は後続の UI 変更に使う確認計画です。
自動化候補を列挙している箇所は、検査を実装済みという意味ではありません。
この文書の追加では workflow、scripts、tokens の値を変更しません。

## 数値とパターンの読み方

通常文字は 4.5:1、意味を伝える操作境界などは 3:1 を基準に確認します。
大きな文字や無効部品などには WCAG の条件と例外があるため、該当箇所で確認します。
既存 tokens が無効部品にも文字の可読性を求める方針は、WCAG の例外とは分けて維持します。
contrast checker は alpha 合成、全 hover 状態、実描画、支援技術を網羅しません。

操作対象は既存 token の 44px 相当を設計目標とします。
これは WCAG 2.5.8 AA の原則 24 CSS px とその間隔等の例外を、44px という値へ読み替えたものではありません。
文字間隔の確認は 1.4.12 に従い、文字サイズに対して行高 1.5 倍、段落後の間隔 2 倍、字間 0.12 倍、単語間 0.16 倍を設定して欠落を確認します。
320 CSS px 相当の確認と、文字 200% の確認は別の手順として記録します。

独自 widget が必要な場合は [APG のパターン](https://www.w3.org/WAI/ARIA/apg/patterns/)と[keyboard の解説](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/)を選んで参照します。
ARIA を付けるだけでは keyboard 操作は追加されないため、キー操作と focus を実装と試験で確認します。
APG の例を写したことだけで WCAG の達成や実機相互運用の合格にはしません。

## OS と支援技術の確認

| 環境 | 確認計画と現在の限界 |
| --- | --- |
| Windows の対象アプリ | WebView2 と Narrator で名前、役割、状態通知、keyboard を確認し、OS の高コントラストと DPI 拡大も実測する。未検証 |
| macOS の開発用表示 | WKWebView と VoiceOver の組合せで確認する案。Chrome の表示成功とは別。未検証 |
| Linux の開発用表示 | WebKitGTK と利用する支援技術（例：Orca）の組合せで確認する案。ディストリビューションと版も記録。未検証 |

上記は対応 OS を追加する宣言ではありません。
host と controller の[対応範囲](status.md#osと役割ごとの範囲)を維持します。
既存 Tkinter を変更する場合も対象 OS の実操作を確認し、WebView の DOM 検査の成功を流用しません。
Tauri の拡大機能やキーの扱いには[プラットフォーム差](https://v2.tauri.app/reference/javascript/api/namespacewebview/#webviewoptions)があるため、使用する版と設定で再確認します。
この確認計画を理由に toolchain、支援技術、WebView2、OS 設定を勝手に追加変更しません。

## 証跡と例外の記録

各 PR には次を短く記録します。

1. 対象 head と部品またはフロー、関連する UI 参照名と WCAG 番号。
2. OS、アプリと WebView、支援技術の版、表示言語、zoom、DPI など結果に影響する設定。
3. 秘密のない入力、操作手順、期待した結果、実測結果と判定（成功、失敗、未検証、理由付き対象外）。
4. 画像、操作結果、匿名化した通知内容。通信の終了根拠は既存契約の証跡と区別して関連づける。
5. 例外の理由、影響する利用者と操作、代案、判断者、追跡 Issue、再確認時期。

WCAG が規定する例外を使う場合は、該当基準と適用根拠を示します。
プロジェクト内の例外承認だけで WCAG の未達を合格にしたり、既存安全契約を緩めたりしません。
確認環境を用意できない状態は「未検証」であり、「対象外」ではありません。
過去の失敗と未達を、新しい成功結果で消しません。

## 現在ある証拠

公開済みの[トークン検証](tauri-design-verification.md)は、120 tokens、23 組の contrast と macOS Chrome 上の限定した表示と操作の結果です。
この基準案の追加では再測定や新しい UI 操作試験を行っていません。
320 CSS px、全フローの全 A / AA 基準、screen reader、OS の高コントラスト、native WebView は合格済みとしません。
ユーザーによる実機確認は現在実施できず、未検証のまま残します。
Python CI と token checker が成功しても、全体の a11y、実通信、配布物、44条件の達成を意味しません。
