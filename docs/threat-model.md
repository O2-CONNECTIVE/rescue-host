# Rescue Hostの脅威モデル

[安全要件](security.md) / [通信契約](communication-contract.md) / [接続再開の条件](SECURITY_BACKEND_CONTRACT.md)

製品の新規接続ゲートは閉鎖しており、本番利用できません。
対象は[通信契約の固定参照](communication-contract.md#対象版と根拠)と、2026-10-27時点の[受入Issue #1](https://github.com/O2-CONNECTIVE/rescue-host/issues/1)です。
公開main、未公開評価ソースの限定した観察、将来の製品要件を区別します。
本書は脅威と残る境界を整理し、既存44条件の定義や合否を変更しません。

## 保護する資産

- ホストのデータ、認証情報、通常ユーザーの操作権限と、管理者権限への境界。
- 起動単位の許可鍵集合、方針、起動世代、最大期限、短期leaseと更新権限。
- 既存SSH/TCP通信、接続処理中のソケット、listener、worker、所有プロセスと収容枠。
- 配布artifactとその版、依存物、host keyの信頼設定。
- 接続情報、鍵、状態記録、回復情報、検証結果と、終了を確認できたかどうかの正確な表示。

## 信頼境界と攻撃者

| 境界 | 想定する攻撃者と信頼の限界 |
| --- | --- |
| 遠隔クライアント → 外側Go SSH | 未許可鍵の利用者、許可鍵を持つ悪意あるゲスト、不正要求や過剰要求を送る相手。鍵照会だけでは秘密鍵所持を証明しない |
| relay → ホスト | 盗聴、改変、遅延、分断、再接続を起こす経路と、侵害されたrelay。信頼する試験relayとhost keyの確認が前提で、実relay統合は未検証 |
| UI/WebView → Rust adapter → Go | UI侵害、細工されたIPC入力、古いevent、要求再送。UIから来た許可表示や値をGoの認可根拠にしない。Tauri adapterは未配線 |
| ゲスト主体 → supervisorと状態 | 同一ユーザーならファイル、pipe、プロセスへの干渉が可能な範囲が残る。独立した保護主体、ACL、認証付きIPCは未実証 |
| 外側転送 → 内側SSHとhelper | 外側の宛先制約は暗号化された内側操作を制御しない。restricted/fullの内側認可は別に必要 |
| 配布元 → ダウンロードと実行 | artifactや依存物、hash一覧、ビルド経路の改ざん。評価helperのhash一致だけで配布元と検証器の独立性は得られない |

OS管理者、kernel、保護側の資格情報を掌握した攻撃者に対する同一OS内の強制停止保証は目標に含めません。
一方、通常ゲストによる同一ユーザー領域への干渉は残すべき脅威で、非目標として除外しません。
Go内のtimerと所有参照は、プロセスごと停止されると実行できません。

## 脅威と既存受入条件の対応

表のIDは既存受入の参照です。
「部分達成」は限定fixtureの証拠で、条件全体の達成ではありません。
最新判定と必要証跡はIssue #1を参照します。

| 脅威 | 実装で観察した防御または必要な境界 | 既存IDと残条件 |
| --- | --- | --- |
| 未許可鍵、外部鍵の暗黙追加、証明書や別方式での認証 | Go基盤候補は起動時のraw Ed25519集合を固定し、起動名とactiveを照合。追加認証源へ依存しない | L-A01/A02/A04/A05。部分達成。固定22番と全経路の独立観測は不足 |
| signature-less query、署名再利用、照会後失効 | 候補鍵照会と署名検証後callbackの両方で判定。署名の検証自体は固定SSHライブラリに委ねる | L-A03/A07、L-R09。部分達成。不正packetの全網羅ではない |
| host key不一致とrelay経路の追加認可 | host keyの固定照合と、relayを追加の認可源にしない設計が必要 | L-A06、U-01/U-04。ローカル参考証拠のみで、U全件は未検証 |
| shell、逆転送、未知channel、global/channel requestで権限拡大 | Go候補は外側 `direct-tcpip` 以外を拒否し、制御要求を拒否。内側shell/helperの制限は別境界 | L-C01〜C04、W-07。Lは部分達成、W-07は未検証 |
| 宛先別表記、port変換、originator偽装、動的転送による迂回 | wireのliteral IPv4とuint32 22を完全一致で判定。固定dialへ渡す引数は受け取らない。originatorは認証主体にしない | L-D01〜D06。D01/D06は未検証、他は部分達成。高位fixtureを固定22番の証明にしない |
| 不正長、過剰要求、handshakeやchannelによる資源枯渇 | payload上限と有限収容枠、接続中の予約を保持する。一般的なDoS耐性の認定はない | L-C05〜C07、L-R04/R05。部分達成。全parserのfuzzと大規模負荷は未認定 |
| 古い世代の更新、重複や逆順、失効後の復活 | Go候補はIdentityと増加連番を照合し、最大期限を延長しない。UI側の要求IDとIPC認証は未決定 | L-R02/R03/R08〜R11、W-05。Lは部分達成、W-05は未検証 |
| UI停止、親死、pipe喪失、監視停止で期限強制を失う | 評価版のEOF、自己Job、親予算、子TTLは限定モデル。保護側が期限と強制手段を所有する製品境界が必要 | L-R12、W-01〜W-05、U-03。Lは部分達成、W/Uは未検証 |
| close無応答、背圧、切断失敗を終了成功に見せる | 所有参照と失敗を保持し、終了確認不能を区別。独立停止経路と保護監督が必要 | L-R01/R06/R07、W-03、U-02。R07はNOT_MET、Windows背圧は未検証 |
| inner操作の継続、切り離したprocess、既実行の変更 | TCP遮断と操作の取消を区別し、所有できるprocess群を別に実証する | W-06/W-07。未検証。終了したTCPだけでは内側副作用の取消を保証しない |
| 秘密、接続token、実環境情報のログ流出 | 状態保存から接続commandを除く既存処理と公開前の選別。評価evidenceや例外文字列を自動的に公開可能と見なさない | U-04、L-R12に関連。専用の漏洩合格IDを新設した扱いにはしない |
| 配布改ざん、未対応版、旧CLIや別入口での迂回 | 固定artifactの照合、未対応版拒否、製品gateと旧経路の閉鎖を維持 | U-04/U-05。未検証。配布元とhashの同時侵害、署名と再現ビルドは残課題 |

## 非目標と残余リスク

今回の文書整備は、サービス起動、ACL変更、実relay接続、製品ゲート解除、配布承認を含みません。
Rust/Tauriの採用、GUIの状態見本、モックの成功は、安全境界の証明になりません。
失効前に相手へ渡したデータ、取得された秘密、既に実行した副作用、所有外のprocessを取り消す保証はありません。
内側に管理者権限を与えたまま同一OSの監督を防御境界とする保証もありません。

| 継続するリスク | 追跡と製品判定への影響 |
| --- | --- |
| 二重停止故障時の物理TCP遮断 | L-R07は **NOT_MET**。[Issue #5](https://github.com/O2-CONNECTIVE/rescue-host/issues/5)。認可状態が失効しても、両close経路故障時のraw canary到達を消さない |
| Windowsの背圧 | L-R06の当該caseは未検証。[Issue #6](https://github.com/O2-CONNECTIVE/rescue-host/issues/6)。前提未成立の失敗履歴と明示未実施を成功へ置換しない |
| 保護された独立principalのsupervisor | W全7件が未検証。[Issue #12](https://github.com/O2-CONNECTIVE/rescue-host/issues/12)。同一ユーザーの自己子、自己Job、TTLは代用しない |
| 固定22番の正例と不在時、専用隔離環境 | L-D01/D06は未検証。[Issue #11](https://github.com/O2-CONNECTIVE/rescue-host/issues/11)。既存sshdに接続して穴埋めしない |
| 実relayと配布物の統合 | U全5件が未検証。[Issue #13](https://github.com/O2-CONNECTIVE/rescue-host/issues/13)。ネットワーク条件、信頼する版、両端観測が不足 |

受入44条件は部分達成29、未達1、未検証14、完全達成0です。
mainへのコード統合、限定評価物の確認、本番利用可能の判定は別々です。
検査中の通信やcloseを無期限に待たない設計でも、OS停止中とsleep中にコードを実行する保証は得られません。
本番ゲート閉鎖を維持し、条件全体の証拠と対象版がそろった時にだけ判定を更新します。
