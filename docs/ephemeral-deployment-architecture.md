# 単発版の配置と責任分担

[構成](architecture.md) / [安全要件](security.md) / [配置の受入計画](ephemeral-deployment-acceptance.md)

上位配置は、運営中継をコンテナ、顧客端末を同梱ネイティブと一時非管理者guestにする方針を採用済みです。
本人認証は[指定OperatorSIDと実message認証](adr/0002-operator-sid-policy.md)の方針Bを採用済みです。
Windows実行方式、認証入口の実配置と初版のSSH機能範囲は未決または未実証です。
配置の採用は実装済みや安全性の認定を意味せず、実SSHとWindows保護は未検証で、新規接続gateは閉鎖を維持します。
本書は実機OS変更、資格情報作成、外部デプロイ、接続や公開を実行する指示ではありません。

## 配置と所有

| 配置 | 所有する責任 |
| --- | --- |
| 運営中継コンテナ | 接続の取次ぎと端末まで暗号化されたSSH streamの配送。運営環境の依存物と更新、再起動を管理する |
| 顧客端末の同梱ネイティブ | 本人承認、許可鍵と方針、起動同一性と期限、guest準備、実行前検査、通信と処理の失効/停止、所有資源の回収を管理する |
| 一時非管理者guest | 承認された操作を実行する。監督や許可の更新権限、管理者権限は持たない |

顧客端末へDocker、WSL、Hyper-V等のコンテナ実行基盤の準備を要求しない配置です。
OSやGUIの前提条件、管理者許可、guest準備と回収が不要という意味ではありません。
利用時の所要時間は未実測で、起動時間の数値目標は確定していません。
必要な管理者操作の許可と、guestへの管理者権限付与は区別します。

既存SSHのservice、設定、鍵、共用DefaultShell、portを変更、置換、奪取しません。
今回の専用資源だけを所有し、二重起動、旧版、削除待ち、他主体の同名資源や所有不明を理由に既存資源を停止/削除しません。
現在の物理固定宛先と新しい専用接続経路の整合は未解決であり、宛先変更を暗黙に実装済みとは扱いません。

## 中継認証と作業許可

中継が持つ情報は配送用の不透明な識別子、現在のtransport対応と必要最小限の接続metadataに限る設計です。
通信相手のIP等は中継から観測され得るため、保存項目、保持期間、アクセスと破棄の方針は別途確定します。
中継自身への接続認証やTLS等の資格と、端末の作業grantを分離します。
中継の設定や再登録で端末の許可鍵集合、操作範囲、期限を追加/拡張できる仕組みにはしません。
遠隔の秘密鍵、端末host keyの秘密値、Windows guestのpassword/tokenを中継へ預けず、作業streamを中継で平文保存しない方針です。
今回の端末host keyを遠隔側が照合する方法も、配布と接続の契約で固定します。

端末は正規operatorの実message認証を行い、承認recordと実行対象を同じ起動へ結びます。
認証後のログオン同一性と本人認証を混同せず、別ログオンへ旧grantを移譲しません。
TTL、非活動期限、短lease、実行前検査と停止の所有者を端末側に置きます。
中継の稼働状態やkeepaliveだけで作業grantを更新しません。

## 切断と再起動と撤去

中継停止や再起動で論理接続が失われたら、端末側が旧grantを失効させ、既存通信と対象処理の停止へ進みます。
喪失検出や期限強制を中継からの通知だけに依存させません。
同じ配送ID、コンテナ名、再登録したtransportや保存metadataから旧grantを復元せず、再接続には新しい承認と起動同一性が必要です。
中継再起動でTTLを延長したり、鍵所持だけで旧作業を再開したりしません。

中継コンテナの削除は、端末のguest account、process、Job、profileやfileの削除完了を意味しません。
端末側が許可失効、実停止、guest無効化、所有資源の撤去を別々に確認します。
削除失敗でも接続権限を復活させず、未確認の終了を成功表示にしません。
再起動後は旧許可を復元せず、保護された回収情報を今回所有する資源の清掃にだけ使います。
実行済み変更の巻戻しは、接続権の失効と分けて扱います。

## 未決と依存順

未決はWindows実行方式、SSH機能範囲、TCP制約の対象、非活動の定義、喪失検出と物理停止上限、外部ログオン/代理起動の防止、中継metadata保持、署名更新と回復の具体化です。
以下は後続タスクの案で、実行の承認ではありません。

| 順序と依存 | 後続タスク | 完了条件 |
| --- | --- | --- |
| T0 | 配置と責任分担の文書統合 | 採用済み配置、未決方式、未実証を区別し、既存受入合否とgateを維持 |
| T1 ← T0 | 機能と実行方式の判断 | 要求機能、実行方式、対応host条件、TCP制約、idleと停止上限を明示。成立を調べるspikeの対象と棄却条件を確定 |
| T2 ← T1 | 端末と中継の認可/所有契約 | 同じ承認record、段階別資格、実認証、期限と版を結び、中継資格の流用と旧grant復元を禁止 |
| T3 ← T2 | 端末nativeの実行と回復 | 正規guest token、同実target、限定継承、Job/profile/IPC、resumeと失効競合、実停止と残留回収を接続 |
| T4 ← T2 | 中継containerの配送と再起動 | 端末までの暗号化、metadata方針、誤配送/切断時拒否、再起動後の旧許可拒否を実装。T3と独立部分だけ並行可能 |
| T5 ← T3,T4 | 同梱物とGUIの縦断 | 固定された署名artifactを使い、既存SSH非破壊と失効/停止/撤去の別表示を維持 |
| T6 ← T5 | 候補固定の実機受入 | 対象と操作を別途承認し、正常/敵対/故障/回復を独立観測。未実行や取得不能を合格へ変えない |
| T7 ← T6 | 有効化と配布可否の判断 | 実証できた範囲と不足を照合。コード統合やCI成功を実接続/外部公開の許可へ転用しない |

実装、実設定と接続の評価は、それぞれ対象、影響、復元手順と既存承認の範囲を確認してから行います。
[配置の受入計画](ephemeral-deployment-acceptance.md)は既存受入の補助であり、合否を書き換えません。
