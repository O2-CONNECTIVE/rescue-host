# リポジトリの配置方針

[READMEへ戻る](../README.md)

ソース、正式文書、テスト、公開用の検証記録を区別し、ビルドと試験が参照する既存パスを保ちます。
この方針は配置上の区別を定めるもので、機能の提供段階や検証済み範囲を変更しません。
提供状況は[実装と検証の状態](status.md)を参照してください。

## 維持する配置

| 場所 | 用途 | 配置のルール |
| --- | --- | --- |
| `src/` | Pythonの製品ソース | 既存の起動方法とモジュール探索を維持する |
| `tests/` | Pythonテストと模擬実行ファイル | unittestの探索対象を保ち、実行ログを混在させない |
| `docs/` | 現行の構成、開発、安全要件、回復、提供状況の説明 | READMEから案内し、詳細を用途別に置く |
| `docs/assets/` | 文書が参照する構成図と画像 | 文書との相対リンクを保つ |
| `assets/` | 実行とビルドに必要な資材 | 同梱先や読み込みパスを変更する場合はビルドも確認する |
| `docs/history/verification/` | 公開用に選別した既存の検証記録 | 対象版、環境、範囲、未検証事項を対応付ける。作業ログを自動追加しない |
| ルートの `README.md` | プロジェクトと詳細文書への入口 | 起動方法と提供状況への案内を保つ |
| ルートのビルドスクリプトと依存定義 | 再現に必要なビルド入力 | スクリプト自身からの相対パスを保つ |
| `docs/history/` | 公開済みの旧引き継ぎ、安全性レビューと検証記録 | 履歴を保全し、現行文書と区別する |
| ルートの変更履歴とライセンス | プロジェクトの履歴と利用条件 | 入口として維持する |

Go Backendを統合する場合は `backend/` を実装とGo moduleの単位にし、`*_test.go` はGoの標準的な配置に合わせて対象パッケージと同じディレクトリに置きます。
この規約はBackendが公開版へ統合済みであることを示しません。
配置整理だけを理由にPythonのパッケージ構造やGoのmodule境界を変更しません。

## 一時作業と正式handoffの区別

作業単位のメモ、一時handoff、変更前snapshot、生の実行ログ、キャッシュは、原則としてリポジトリ外の作業領域に置きます。
新しい作業補助をリポジトリ内へ置く必要がある場合は、Git除外対象の `.work/` 配下を使います。
たとえば `.work/handoffs/`、`.work/snapshots/`、`.work/evidence/` と用途を分けます。
`.work/` は新規作業の規約で、既存の参照先を一括移動する指示ではありません。

一時handoffには対象版、変更範囲、未追跡ファイルの有無、未達、次に確認する入口を記します。
後続の開発者が必要とする説明は `docs/` へ整理し、公開用に確認してから追跡対象にします。
既存の引き継ぎは `docs/history/` に追跡済みの履歴文書として保ちます。

Gitの除外設定は公開防止や安全な保管を保証しません。
トークン、秘密鍵、個人情報、端末固有の接続情報を文書や配布物へ取り込まず、公開候補は追加前に内容を確認します。
除外済みでも、すでに追跡されているファイルの扱いは変わりません。

## ビルドと配布物

既存の `build/`、`dist/`、`vendor/`、`third_party/` の役割とビルドスクリプトからの参照を維持します。
Git除外対象であることを、削除可能という意味には使いません。
依存バイナリやライセンスは、ビルド入力または配布時の同梱物として必要になる場合があります。
具体的な手順は[開発とオフライン検証](development.md)とビルドスクリプトを参照してください。

配布候補は中間生成物と区別し、対象ソース、依存版、必要なライセンス、検証記録との対応を確認します。
失敗した試行や既知の未達を、最終合格の記録で上書きしません。
生の証跡と端末固有の作業履歴はローカルに保管し、公開する記録は必要な範囲を選別します。

## 配置を変更するときの確認

既存ファイルを動かす場合は、READMEとdocsのリンク、Pythonのimportとテスト探索、Go module、ビルドスクリプト、同梱物を確認します。
進行中の作業が参照しているパスは、その用途が終了するまで保持します。
一時物の整理では削除より復元可能な退避を優先し、元の位置と戻し方を記録します。
