# オフラインのバックエンド制御モデル（v0.2開発）

`rescue_policy.py` と `rescue_lease.py` は標準ライブラリだけで動く設計検証用の中核処理です。
**SSHサーバー、Windowsサービス、実認証、実プロセス停止、安全なIPC、独立して期限を強制するタイマーではありません。**
`require_secure_session_backend()` の常時拒否は維持します。このモデルの `ACTIVE`・`READY` を本番接続の許可証に使ってはいけません。

## GUIとモード

`Settings.to_operation_policy()` は検証したGUI設定を変更不能な `OperationPolicy` へ変換します。これは設定から方針への変換であり、実セッションの起動・認可ではありません。
`OperationPolicy(operation_mode="restricted" | "full")` の既定値は `restricted` です。旧接続方式の `ssh`・`terminal` とは別の概念です。

- 両モードとも外側のゲートウェイで許可するのは `direct-tcpip`、**文字列 `127.0.0.1`、整数型 `22` の完全一致**だけです。セッション、シェル、コマンド実行、PTY、サブシステム、SFTP、逆向き転送、エージェント・X11転送は許可しません。
- 制限付きモード（`restricted`）は `diagnostics.system`、`diagnostics.network`、`repair.restart-approved-service` の抽象ヘルパーIDだけを許可します。引数は空タプルに固定し、自由文、任意コマンド、任意サービス名は受け付けません。ヘルパー実体、承認済みサービスの定義、OSのACLは未実装です。これらのIDをそのままCLIに渡してはいけません。
- フル操作モード（`full`）は内側SSHの通常のシェル操作を意図しますが、**管理者昇格の許可ではありません**。両モードとも `allows_admin=False` です。内側アカウントに管理権限を与えないことは、実際の権限境界として別途実証が必要です。
- 外側のTCP制約では、暗号化された内側SSHのシェル・ヘルパー操作を制御できません。制限付きモードには内側SSHと保護されたヘルパーによる別の強制が必要です。

方針のダイジェストは、モード、スキーマ、固定宛先、許可ヘルパーを含む正規化JSONのSHA-256です。
`SessionIdentity` は `schema=1`・`launch_id`・`run_epoch`・`policy_digest` を持ちます。ID生成、一意性の永続保証、IPC認証は行いません。実装側で再利用を禁止する必要があります。

## ライフサイクルと期限

`OfflineSessionAuthority` は1回の起動について `prepared → ready → active → revoking → terminated` の状態を管理します。同一性の異なる準備・有効化・更新・接続要求を拒否し、失効中・終了済みから再開しません。

生成時に最大利用時間（上限7,200秒＝120分）、短期リース（上限60秒）、チャネル収容上限を固定し、更新しても最大期限は延びません。試験用の短い時間も許可します。GUIの利用時間下限とは別で、上限はバックエンド側が所有します。更新には厳密に増加する整数連番を必須とし、時計は実時刻とスリープを含む経過時間の組を注入します。いずれかの期限到達、時計後退、読み取り失敗、非有限値で失効へ進みます。

`open_channel(..., dial=...)` は許可判定後にアドレス引数なしでアダプターを呼びます。本物のアダプターは必ず固定の `tcp4 127.0.0.1:22` だけへ接続する必要があります。モックの動作ではその保証は得られません。
Go の承認済runtimeは[ADR-0003の追補](adr/0003-owned-guest-workload.md#追補-wireのliteral宛先と所有内側endpoint)により、同じwire一致を物理TCPではなく製品所有の内側SSH endpointへ渡すsource候補です。wireのliteralとdigestは物理宛先の証明ではありません。

収容数は接続処理中と既存チャネルの合計です。接続処理中の失効後に返ったチャネルも閉じます。プロセス・通信・チャネルの終了処理に失敗した場合は参照と失敗型を残し、失効中のまま `poll()`・`revoke()` で再試行します。停止の受付応答だけを終了証明とみなす設計ではありませんが、モデルの終了処理成功はアダプターが正しく実装されている前提です。

## 本番利用を妨げる未解決事項

- `poll()` は呼び出し側に依存します。プロセス停止・無応答・スリープ中の強制力はありません。Windowsの単調時計がスリープ・再起動をどう扱うかも未検証です。
- 同期的な `close()`・`dial()` が戻らなければ完了しません。処理中の接続は保持しますが取消機構は未実装です。Goアダプターの期限・取消、期限内に完了する非停止型終了処理、保護された監督が必要です。
- 公開鍵認証、SSH要求・チャネル処理、固定TCP宛先への接続、ローカル接続経路の無効化は、Go・Uptermの改修側で実装し負例試験が必要です。
- 分離した実行主体、保護サービス、Job Object、認証付きリースIPC、起動世代の生成・保護は未実装です。
- 外側通信を閉じても、内側sshdが生成した切り離されたプロセス、別接続、実行済み変更は消えません。フル操作で管理者権限を与えると、同じOSの監督を防御境界にはできません。
- モック試験は実接続、権限境界、失効時間上限の証拠ではありません。隔離VM・承認済み中継の試験には別途承認が必要です。

## 実行

```sh
python -m unittest discover -s tests -p 'test_backend*' -v
```

このモデル試験では、実ポートの待ち受け、ネットワーク通信、認証情報生成、OS設定変更を行いません。
