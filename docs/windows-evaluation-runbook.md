## 対象と現在できること

本書はセットアップ、限定検証、撤去を準備する手順で、実行済みの報告ではありません。
基点はmain `929d516173dbbf772ba224d5dde500f6e51f1501` です。
実SSHは未有効で、Tauriの開始と停止も無効です。
固定provisioning、保護されたstdioとstderrの回収、許可0でのSCM制御面ready、正規operatorの承認入口、受理transportは未完成です。
Windows clientとnative bootstrapの準備コード、認証交換の所有管理はmainにありますが、実pipe認証や実SSHは検証済みではありません。
基点の[Go](https://github.com/O2-CONNECTIVE/rescue-host/actions/runs/40852895398)、[Python](https://github.com/O2-CONNECTIVE/rescue-host/actions/runs/40852895341)、[日本語commit](https://github.com/O2-CONNECTIVE/rescue-host/actions/runs/40852895365)のCI成功は、実機受け入れの合格ではありません。
今回は文書整備だけを行い、実設定変更、サービスやアカウントの作成、鍵や資格情報の生成、SSH接続は行いません。

評価対象はWindows 11 Pro 23H2 x64の旧OS互換性です。
23H2のHome / Proは[Microsoftのサポート終了案内](https://learn.microsoft.com/en-us/lifecycle/announcements/windows-11-23h2-end-of-updates-home-pro)の対象で、限定評価の成功を本番の安全性や製品のOS対応保証にしません。
OS更新を全評価の一律の前提にはせず、更新や保護設定の変更もこの手順では行いません。
OS版、CPU、既存Runtimeと候補の組合せごとに結果を残します。

GUI評価版の起動と表示は既存の利用者確認報告を再利用し、同じ候補と範囲の再確認を必須にしません。
報告から対象版や環境が特定できない項目は未確認として残し、新候補や環境差分で再確認が必要になった場合だけ対象を指定します。
GUIの表示確認を、以下の実通信やOS保護の合格へ流用しません。

初期対象は遠隔の非管理者ゲストから監督と停止処理を保護する範囲です。
host操作ユーザーまたは管理者が既に侵害された環境と、管理者ゲストは保証対象外です。
P2 handshakeの専用再現や代替試験は追加しません。
製品gateと既知のNOT_MET / UNVERIFIEDは維持します。

## 作業前の読み取り確認

1. 評価責任者が対象候補の完全source SHA、ZIP / EXEのhash、manifest、CI URL、実評価の接続経路、未達と未実行項目を照合します。失敗した候補や別headの成功を混ぜません。
2. OS版とCPU、既存WebView2 / 必要Runtime、実行ユーザーの権限を読み取り確認します。確認不能ならその項目を記録し、依存を自動導入しません。
3. 既存sshd、22番の利用有無、同名サービスやアカウント、候補の保存先やprofileとの衝突を、予定した範囲だけ読み取り確認します。既存sshdへの接続、停止、設定読替え、22番の待受作成は行いません。
4. 業務データ、本番鍵、既存認証設定に作用しない対象であることと、作成予定資源を個別に識別して撤去できることを確認します。既存profileや同名資源があれば上書きせず、実装ownerへ戻します。

OS情報の確認例は次の読み取りだけです。
端末名やIPを収集するための一括inventoryは行いません。

```powershell
Get-CimInstance Win32_OperatingSystem |
  Select-Object Caption, Version, BuildNumber, OSArchitecture
```

この段階では、未確定の保存先を仮定してファイルを作ったり、候補のサービスを登録したりしません。
個別端末名、IP、実ユーザー名、SID、絶対パス、生ログは非公開の作業記録にとどめます。

## 実装ownerへ確認する項目

以下は未確定または実機未検証です。
コード中の定数、型、SIDやDACLの候補を、そのまま採用済みの設定値や導入手順にはしません。
実装ownerが候補sourceに対応する値と手順を提示し、統合ownerが依存と検証境界を確認します。

| 項目 | 操作前に確定する内容 |
| --- | --- |
| 起動とサービス | 配布EXE、サービス名、登録と起動の入口、権限、起動失敗時の挙動、通常停止と撤去の方法。現service hostの準備名は採用決定ではない |
| 実行主体 | service / operator / guestの実アカウントとSID、非管理者guestの実効権限、分離方式。LocalServiceやper-service SIDは候補で、fallbackを推定しない |
| ACLとIPC | 対象資源、適用する権限、正規operatorの承認口、guest拒否、peer identity照合、権限変更前後の確認方法 |
| 保存と記録 | 設定、方針、ログ、profileの保存先と所有者、既存資源との衝突、保管期間、公開前の秘匿、撤去対象。永続grantの採用は初期評価の前提にしない |
| 鍵と資格情報 | 必要性、評価専用に限定する方法、生成または受渡しの担当、保管、失効、破棄。本書では生成せず、本番鍵の流用も指定しない |
| 承認と期限 | 許可鍵、固定宛先、操作範囲、最大期限、短lease、世代、停止口、独立した期限執行、許可0からの再承認 |
| 所有と終了 | 今回起動したprocess / Job / pipe / 接続の同定、終了予算、終了確認不能の表示、失効と物理終了の別観測、回収失敗時の扱い |
| 検証の接続先 | 承認された評価専用の相手と資源、既存sshd / 22番 / 業務データへの非干渉を成立させる方法。現行の禁止を別ポートの代替合格で埋めない |

値や復元方法が決まっていない操作だけを保留し、文書確認や他の独立した読み取りは継続できます。
UIやOSの保護を回避して先へ進む手順は作りません。

## 変更一覧と実行時の承認

変更を行う直前に、評価責任者が次の一覧を具体化し、利用者へ実行時の承認を求めます。
本書のmergeや「23H2で評価する」という方針だけを、サービス登録、権限変更、鍵生成、再起動、実接続の承認にしません。
毎回別の管理者サインインを要求する方式は初期必須条件に追加しません。
必要な操作権限と正規operator承認は、確定した実装で個別に確認します。

| 記録欄 | 承認前に提示する内容 |
| --- | --- |
| 候補と対象 | source SHA、artifact hash、非公開の対象識別子、実評価の接続経路、試験する機能としない機能 |
| 変更 | 追加する各資源、変更前後の値、実行主体、管理者権限の要否、既存資源へ作用しない根拠 |
| 実行 | 確定した操作と順序、接続先、回数、時間上限、観測方法、停止条件 |
| 撤去 | 作成資源の識別方法、失効、終了確認、削除と復元の順序、取得不能時の保留方法 |
| 証跡 | 非公開記録の保管先、公開する要約、秘密を含めない項目 |

承認は対象候補、対象資源、操作、範囲に結びます。
差分が生じた操作は変更一覧へ戻し、拒否された操作を別経路や別agentで実行しません。
本書の作成時点では実行承認を求める設定値や操作が未確定なので、実行コマンドを埋めていません。

### 実機試験の前提と判定

以下の全行は未実施です。
共通前提は固定sourceと評価物、専用環境、対象・操作・時間上限の承認、既存資源への非干渉、独立観測手段の確定です。
証拠はsource SHA、対象範囲、匿名の結果と経過時間を記録し、端末IP、ユーザー名、鍵、秘密、生ログを公開しません。
本人の停止要求、対象や承認の不一致、予期しない資源への作用、観測不能、期限超過では中止します。

| 対象 | 前提と手順 | 合否・匿名証拠 | 個別の中止条件 |
| --- | --- | --- | --- |
| 承認と分離 | 正規operatorの承認口と非管理者guestの実効権限を確認し、guestからの制御IPC要求を検査する | 正規承認とguest拒否を別に記録。表示だけでgrantを成立させない | 主体や権限を確認できない |
| 正常接続 | 保護承認と専用経路の確立後、許可された評価専用鍵で署名認証し、許可先と無害な往復を行う | 同じ候補と経路で認証後の両端の往復を観測し結果を記録 | 承認や相手の同一性が確認不能 |
| 別鍵拒否 | 専用環境で許可集合外の評価専用鍵を提示する | 署名認証を拒否し、許可先への接続と操作が発生しない。拒否とdial数を記録 | 鍵の区別やdial観測が不能 |
| 禁止TCP転送先 | 許可外の宛先要求を送り、既存sshdや22番には接続しない | 許可外の要求を拒否し、禁止先へのdial 0を独立観測。固定22の正例は別途記録 | 禁止先へのdialまたは観測不能 |
| 停止 | 接続中に正規の停止を要求し、受付、失効、両端終端、所有processとJob回収を観測 | 旧許可の新規・再接続を拒否し、既存通信の両端終端と回収を別記録 | 終了確認不能または所有対象の同定不能 |
| idle・最大期限 | 無操作idleと短lease喪失、最大期限を別に確認。idleの意味と閾値は未決で、決定までは未実施 | 確定した期限に応じて失効、新規・再接続拒否、両端終端を観測し、閾値と経過を記録 | 期限の観測不能、未決idleをleaseに置換する必要が生じた |
| 強制終了 | 個別に承認した今回所有の対象だけを異常終了し、保護側の失効と回収を観測 | 旧許可の失効、両端終端と残存の有無を記録。強制回収を正常終了にしない | 所有同定不能または終了確認不能 |
| 再起動と清掃 | PCと監督serviceの再起動を別々に承認し、旧許可拒否、再承認、今回資源の撤去を確認 | 許可0、旧grant拒否、削除前の失効、再承認、資源と待受の残存を別記録 | 旧許可の復活、所有不明、削除・回収の確認不能 |
| 失敗時のUI | 確定した対象版で失敗、取得不能、終了確認不能を観測する | 未接続、停止要求済み、終了未確認を区別し、受付だけで終了済みにしない | 表示の根拠が確認不能 |

受入の定義は[親Issue #1](https://github.com/O2-CONNECTIVE/rescue-host/issues/1)を正本とし、この表は実施準備の分類にとどめます。
初回の限定実SSH評価 #7 と、既存44条件の達成やGAは別判定です。
全44条件の達成を初回評価の一律の前提に追加せず、対象経路で必要な保護と実証、実行承認の不足を個別に判定します。
実relayを通さない試験は、そのrelay経路の成立証明にはしません。
操作の無入力時間に基づくidle失効は未定義で、更新を失った短leaseの失効とは区別し、新しい要件にしません。
一行の部分確認を既存条件全体のpassedへ変更しません。
失敗、timeout、取得不能、0件、強制cleanupだけで終わった確認を成功へ変換せず、成功するまでの再実行もしません。

## ログと失効の確認

1. 候補sourceとhash、環境の差分、実施行、観測時刻と上限、期待結果と実結果、未実行理由を対応付けます。状態は「成功」「失敗」「未実行」「取得不能」で記録し、認可失効と物理終了の結果を別欄にします。
   同じ起動同一性のGo Close成功、実EOF、readerのjoin、所有processのexitとreapは別々に記録し、Owned 0だけから終了を推定しません。
   hash、nonce、PID、schemaへの適合もgrantの正規承認やIPC認証の証明にはしません。
2. 正規の停止口で今回の許可を失効させ、新規要求拒否、既存通信、process / Job / pipeの終了を個別に確認します。GUIを閉じたこと、鍵ファイルを消したこと、stop receiptだけを終了証明にしません。
3. 終了を確認できなければ「終了未確認」を維持し、追加起動や次の承認へ進みません。確定済みの今回資源の回収手順だけを使い、既存サービスの停止や名前一致による一括終了は行いません。
4. 公開するのは候補SHA、hash、受入ID、結果、秘匿済み固定code、未検証事項の要約だけです。鍵、接続token、資格情報、個別端末名やIP、実SID、絶対パス、生の例外やログ、業務データは公開しません。

## 今回作成した資源だけを撤去する

作業前の資源一覧と作成記録を照合し、今回所有することを確認した対象だけを撤去します。
設定値や対象の所有を確認できなければ削除を保留し、残存と次に必要な確認を報告します。

1. 許可を失効させ、承認された停止方法で今回の通信とprocess群の終了を確認します。失効不能または終了未確認は失敗として残します。
2. 今回作成したIPCやJob等の所有資源を確定手順で回収し、その結果を記録します。通常終了と強制回収を分けます。
3. 作成した場合に限り、今回のサービス登録、評価用アカウント、権限設定、評価専用の資格情報を、承認済みの依存順と復元方法で撤去します。既存同名資源や他用途の権限は変更しません。
4. 今回の展開物と評価専用保存物は、終了確認と必要な証跡の秘匿保存後に削除します。既存WebView2、既存profile、旧Tk state、sshd、22番設定、業務データ、本番鍵は残します。
5. 作業前後を読み取り比較し、残存、復元結果、削除を保留した対象と理由を報告します。取り除いたファイルだけから、実行済みの副作用まで取り消せたとは判断しません。
