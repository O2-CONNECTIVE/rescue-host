# デザインとアクセシビリティの基準案

[README](../README.md) / [開発手順](development.md) / [確認方法と証跡](design-accessibility-verification.md)

救援される人が許可相手、操作範囲、期限、接続状態を読み取り、必要なときに停止できる UI を目指します。
この文書は、既存の[トークン案](tauri-design-tokens.md)から共通部品と画面へ進む際の設計とレビューの基準案です。
新しい画面、Tauri 配線、システム導入は含みません。
追跡は[操作性 #25](https://github.com/O2-CONNECTIVE/rescue-host/issues/25)、[tokens #16](https://github.com/O2-CONNECTIVE/rescue-host/issues/16)、[基盤ロードマップ #22](https://github.com/O2-CONNECTIVE/rescue-host/issues/22)を再利用します。

WCAG 2.2 の A と AA を WebView 内 UI の目標基準案にします。
対象フローに適用する達成基準の洗い出しと、ネイティブ実機の確認は未完了であり、AA 達成は宣言しません。
下表の頻出項目だけで全達成基準を網羅したとは扱いません。
既存[受入44条件](https://github.com/O2-CONNECTIVE/rescue-host/issues/1)の定義と合否は変更しません。

## 基準の採用範囲

**既存必須**は既存の安全契約を UI でも維持する事項、**必須案**は変更箇所の PR で確認する運用の提案、**推奨**は目的に応じて選ぶ参考です。
必須案の採用や具体的な製品判断は #25 で追跡し、文書の追加だけで未実装機能を提供要件にしません。
外部資料の版を更新する際は適用範囲と差分も確認します。

| 公式資料と参照版 | 適用範囲と扱い |
| --- | --- |
| [WCAG 2.2、2024-12-12 Recommendation](https://www.w3.org/TR/2024/REC-WCAG22-20241212/) | WebView 内のページと一連の操作の A / AA を目標とする必須案。該当しない基準と規定の例外は理由を記録する |
| [WCAG2ICT、2025-12-11 Group Note](https://www.w3.org/TR/2025/NOTE-wcag2ict-22-20251211/) | 非 Web ソフトウェアへの読み替えの参考。規範的な準拠基準を追加する文書ではない |
| [WAI-ARIA APG、継続更新版](https://www.w3.org/WAI/ARIA/apg/about/introduction/) | 該当 widget を採用するときの推奨パターン。APG 自体に準拠モデルはない。HTML 標準部品で足りる操作を独自 widget にしない |
| [Windows accessibility、2026-04-08 更新版](https://learn.microsoft.com/en-us/windows/apps/develop/accessibility)と[試験手引き](https://learn.microsoft.com/en-us/windows/apps/design/accessibility/accessibility-testing) | Windows の名前、役割、状態、keyboard、コントラストと支援技術の実機確認に使う必須案。WinUI の API 例を Tauri にそのまま移植しない |
| [Tauri v2 WebView 差](https://v2.tauri.app/reference/webview-versions/) | Windows の WebView2、macOS の WKWebView、Linux の WebKitGTK を分けて確認する技術上の参照。単一ブラウザーの成功を他 OS へ読み替えない |
| [既存のトークン仕様](tauri-design-tokens.md)、[通信契約](communication-contract.md)、[脅威モデル](threat-model.md) | palette の具体値と状態の根拠は各正本を参照。認可と期限の責務、接続ゲートの維持は既存必須 |

継続更新資料の閲覧日は 2026-10-27 です。
WCAG は Web の基準なので、アプリ全体への適用では OS のウィンドウ、メニュー、ダイアログ、アクセシビリティ API も別に確認します。
支援技術との相互運用が確認されるまで、HTML の属性やブラウザーの模擬表示だけでデスクトップ全体の合格を出しません。

## Rescue Host の具体ルール

以下の `UI-01` などはこの文書内のレビュー参照名です。
既存44条件へ追加する受入 ID ではありません。
自動確認、手動確認、既存 ID との関連は[確認表](design-accessibility-verification.md#項目ごとの確認表)にまとめます。

| 参照名 | 扱い | 変更する UI で確認すること |
| --- | --- | --- |
| UI-01 情報と語彙 | 必須案 | 許可相手、操作範囲、期限と現在の状態を先に読める配置にする。同じ操作に同じ日本語を使い、専門語には説明を添える。詳細設定とログは別領域に置く |
| UI-02 許可と接続 | 既存必須 | GUI の設定、残り時間、色を認可の根拠にしない。「接続中」を「安全認証済」と表現しない。バックエンド未接続を明示し、未配線の開始や停止は無効にする |
| UI-03 停止と終了 | 既存必須 | 停止要求、停止中、終了確認済、終了確認不能を分ける。受付応答、通信喪失、画面終了だけで終了確認済へ移さず、未確認の記録を保持する。根拠の扱いは通信契約に従う |
| UI-04 操作の影響 | 必須案 | 停止をログやメニューの奥へ隠さず、状態と近い位置で見つけられるようにする。データ削除などを導入する場合は対象、影響、回復可否を操作前に伝える。確認方法は操作ごとに設計する |
| UI-05 keyboard と focus | 必須案 | マウスなしで使え、見た目と読み順に沿って移動できるようにする。focus を隠さず、状態更新で奪わない。採用する dialog は出入りと focus 復帰を検証する |
| UI-06 名前と読み上げ | 必須案 | 部品の名前、役割、値、無効状態と見出し構造を機械的に伝える。状態変更は必要な通知を届ける一方、残秒を毎秒読み上げたりログ全体を再通知したりしない |
| UI-07 色と拡大 | 必須案 | tokens を使い、色に加えて文言と記号で状態を伝える。文字、余白、境界を揃え、日本語の折返しと長い名前を確認する。文字拡大と狭幅でも停止やエラー説明を欠落させない |
| UI-08 動きと OS 表示 | 必須案 | reduced motion に従い、点滅で状態を伝えない。OS の高コントラスト表示でも境界、focus、記号、文字を残す。ライト以外のテーマは再検証してから追加する |
| UI-09 エラーと回復 | 必須案 | 対象入力の近くで理由と直し方を伝え、読み上げと対応づける。placeholder を label の代わりにしない。失敗や timeout を成功へ変えず、再試行の可否は通信契約に従う |
| UI-10 診断の開示 | 既存必須と必須案 | 秘密や実環境情報をそのまま表示、コピー、公開しない。ログ由来の文字列を HTML として解釈しない。別領域の開閉や選別の操作性は必須案とし、新しいログ出力機能はこの文書で追加しない |
| UI-11 時間制限 | 既存必須と要設計 | Go の期限と失効を維持する。WCAG 2.2.1 の適用と規定の例外を個別に確認し、「セキュリティ目的だから対象外」と一括判断しない。時間内の入力負担への配慮は #25 で設計し、GUI から期限を勝手に延長しない |

停止前の確認 dialog を挟まず要求を送ること、開始前の確認内容、重要通知のタイミングと優先度は、今後 #25 で決める製品提案です。
本書で採用済みの動作や実装済み機能とは扱いません。
終了未確認の記録は[回復処理](recovery.md)に従い、一般的な削除 UI の都合で消しません。

## PR レビューの最小チェック

- [ ] 変更する部品、画面、状態と該当する UI 参照名を示し、既存契約との差分を確認した。
- [ ] 文言、tokens、無効理由、エラーと focus の扱いを確認した。
- [ ] keyboard 操作と状態遷移を確認し、画像だけで操作合格にしていない。
- [ ] 色以外の状態表現、日本語の折返し、拡大、狭幅、reduced motion と高コントラストの影響を確認した。
- [ ] 自動検査と実機確認を分け、対象 head、環境、手順、結果、未検証と例外を記録した。
- [ ] 認可、TTL、停止証拠、秘密の扱いを維持し、UI の検査成功を44条件や製品有効化の合格へ読み替えていない。

変更のない項目には「対象外」と理由を記録します。
確認環境がなければ「未検証」とし、必須案への例外を記録しても WCAG の未達を合格へ変更しません。
例外記録と実機確認の詳細は[確認方法と証跡](design-accessibility-verification.md)を参照してください。
