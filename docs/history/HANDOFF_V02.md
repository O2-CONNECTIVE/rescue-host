# v0.2 開発引き継ぎ（過去版）

> これは0.2.0-dev時点の履歴です。現在は [HANDOFF_V021.md](HANDOFF_V021.md) を優先してください。末尾の明示的な `ended` 応答による自動整理は後続版で撤回し、旧記録は自動削除しません。

## 入力と状態
元添付ZIPのREADME、Pythonソース、テスト、ビルドスクリプトを検査した。元のHANDOFF.mdとレビューレポートは含まれず提供待ち。既存の指摘事項をすべて解消したとの主張はできない。

成果物は**0.2.0-devの安全性修正候補**。実運用可能なv0.2ではない。実UptermのTCP宛先強制機能と保護された失効基盤が不足するため、全新規セッションを閉じた。

## 変更箇所
- rescue_core: 開始ゲート、SSH転送拒否、公開鍵のバイナリ形式検証、安定版バージョン検証、Upterm設定分離、回復状態検証、停止後確認、トークン非永続化。
- rescue_host: GUIとワーカーの二重ゲート、危険な共有無効、停止未確認表示、古いセッション応答の無視、絶対パス保存。
- rescue_watchdog: 起動準備応答、有限期限検証、単調時計併用、停止再試行、失敗時の状態保持。これは同一ユーザーが停止できるベストエフォート補助であり、セキュリティ境界ではない。
- build_windows.ps1: レビュー対象版固定、ローカルバイナリの明示SHA256/ライセンス必須化。
- tests: 模擬ライフサイクル試験を維持し、負例回帰試験追加。

## テストの限界
標準ライブラリunittestで42件成功、compileall成功（Linux/Python 3.12.14、2026-10-26）。模擬実行ファイル、モックによるオフライン試験。実Upterm・公開中継・本番PC・ポート22には接続しない。Windows/Tk画面、PyInstaller EXE、PowerShellビルドスクリプト実行、ACL、実ネットワーク、スリープ・再起動は未検証。

## 継続作業
1. 元HANDOFF/レビューを受領し今回の評価と照合。
2. [バックエンド契約](../SECURITY_BACKEND_CONTRACT.md)に従い保護された転送・失効バックエンドを設計/実装。
3. 回復経路の起動ID検証と実Windows互換性を検証（現状は名前ベースの旧形式）。
4. Windows VMの敵対的接続・停止故障試験、実GUI、署名/依存ハッシュ固定・再現ビルド。
5. 最終レビュー後、実接続/外部公開についてユーザー承認を得る。承認だけを理由に開始ゲートを解除しない。

## 操作上の注意
既存セッション情報が壊れている場合は消さずGUI起動を停止する。別途承認された環境で管理者が事実確認して回復する。回復レコードの有無だけではセッションの終了を証明できない。旧v0.1を別途起動したりUptermを直接実行することまで本アプリは防止しない。

旧セッションの検索で終了コード4（見つからない）でも、実行ファイル・検索環境の同一性が未保証なため終了とは判断せず記録を保持する。当時は明示的な `ended` 応答で自動整理していたが、v0.2.1では旧記録の自動整理を撤回した。この保守的挙動により実Upterm停止後も手動確認が必要な場合がある。
