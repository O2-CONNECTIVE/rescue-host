# 旧セッションの回復と画面終了

[READMEへ戻る](../README.md)

この開発候補は、旧v0.1の保存済みセッションを確認し、停止要求を行う回復経路を備えています。
実Windowsでは未検証で、確実な停止や失効を保証しません。
新規接続、接続情報の共有、転送コマンド生成は無効です。

## 起動と停止要求

GUIは起動時に保存済みの旧記録を読み取り、状態確認や期限に応じた停止要求を行います。
本番PCでは承認前に実行しないでください。
壊れた回復状態は黙って削除せず、ファイルを保持してGUI起動を停止します。
設定の破損は別に扱い、制限付きの既定設定で回復処理の予約を続けます。

旧記録は起動ID、実行ファイル、検索環境の同一性が不足しています。
名前付きの`ended`応答、終了コード4、`not found`だけで終了を証明できず、停止要求後も回復情報と鍵を保持します。
記録を消して解決したことにせず、承認済みの対象環境で実プロセスと通信の終了を確認してください。

GUIは旧セッションを「停止未確認」と表示します。
v0.2.1の起動だけでは、別プロセスの旧セッションを確実に失効させられません。
同一ユーザーの監視も停止を補助する処理にとどまります。

## 画面を閉じるとき

通常の終了操作では停止を要求しますが、この版は旧セッションの終了を検証できず、自動で閉じられない場合があります。
専用の「画面だけ閉じる」は既定「いいえ」の警告確認後に画面だけを終了し、回復情報と鍵を保持します。
**画面終了は接続停止を意味しません。**

停止できても、既に行われた変更や取得された認証情報は元に戻りません。
[安全要件](security.md)と[v0.2.1の公開レビュー](../SECURITY_REVIEW_V021.md)を参照してください。
過去の[引き継ぎ](../HANDOFF_V02.md)と[レビュー](../SECURITY_REVIEW_V02.md)にある明示的な終了応答による自動整理は、v0.2.1で撤回しています。
