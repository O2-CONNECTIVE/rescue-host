# Rescue Host — v0.2.1-dev（安全性修正候補）

**新規接続はすべて無効です。本番利用できるリリースではありません。**
既存のUptermではTCP転送先を127.0.0.1:22だけに強制できず、同じユーザー権限の監視プロセスでは確実な失効も保証できません。安全要件を満たしたように見せないため、GUIと起動ワーカーの両方で開始を拒否します。設定・環境変数で解除するスイッチはありません。

## OS・役割別の対応状況

**現在、実リモート接続を「対応済み」と呼べるOSはありません。** 「救援されるPC」「操作するPC」「開発・試験環境」を区別しています。

凡例：**検証済み**＝記載範囲のみ試験成功／**計画・未検証**＝想定用途だが動作保証なし／**未対応**＝本候補で提供しない。

## プロジェクト構成

![Rescue Hostの構成図。GUI設定から不変方針への変換と独立したオフライン期限モデルは実装済み。開始ゲートは常時拒否。実SSHアダプター、内側sshdの制約、保護されたWindows監督は未実装。](docs/assets/architecture.svg)

[PNGで構成図を開く](docs/assets/architecture.png) · [編集可能なSVG](docs/assets/architecture.svg)

図の実線は実装済み部分、赤い領域は常時拒否する開始ゲート、破線は未実装の計画です。色だけでなく番号・文字・線種でも区別しています。GUIから実セッションへの接続線はありません。これは**ソース構成の説明図であり、実GUIのスクリーンショットではありません**。

- **設定側**：GUIが操作範囲を保存し、`Settings` に不変方針へ変換する `to_operation_policy()` を提供します。GUIがこの関数を呼んで実セッションを起動する処理はありません。
- **オフライン検証側**：`rescue_lease.py` が準備・有効化・失効・終了の状態、期限、接続競合、切断再試行をモデル化します。GUIがこのモデルで実通信を起動する実装はありません。
- **既存記録の回復側**：`rescue_core.py`・`rescue_watchdog.py` は旧記録の検証・停止要求を補助します。監視は同一ユーザー権限であり、安全境界でも確実な失効機構でもありません。
- **将来の安全境界**：実SSH処理、固定宛先への実接続、内側sshdの制約、保護されたWindows監督を別途実装・検証する必要があります。

## この候補でできること
- ソース、設定・公開鍵検証、回復処理をオフラインで検証
- 旧v0.1の保存済みセッションを確認・停止する回復経路（実Windowsでは未検証）
- 旧セッションは終了応答だけで同一性を証明できないため、停止要求後も回復記録を保持。自動で「終了確認済み」にはしない
- Uptermユーザー設定と`UPTERM_*`環境変数の混入防止

既存セッションも安全になったわけではありません。接続共有・転送コマンド生成は無効です。GUIは既存セッションを「停止未確認」と表示します。v0.2.1起動だけでは、別プロセスの旧セッションを確実に失効させられません。

## 操作モードとオフライン制御モデル
GUIで「制限付きの診断・修復」「フル操作」を選択・保存できます。既定は制限付きです。旧設定の接続方式は操作権限と区別して移行します。フル操作の選択は管理者昇格の承認ではありません。**どちらを選んでも実接続は無効です。**

`rescue_policy.py` は不変の操作方針、固定転送先、許可操作IDを検査します。`rescue_lease.py` はセッション同一性、最大期限、短期リース、失効、接続競合と切断再試行の実行可能なオフラインモデルです。GUIから実セッションへ接続する機能はありません。許可操作IDは将来のヘルパー仕様であり、診断・修復コマンド自体は実装していません。

このモデルはSSHサーバー、認証、Windowsサービス、OS権限分離、独立したタイマーを提供しません。呼び出し側が定期確認しない、Pythonがハングする、アダプターの終了処理が戻らない場合まで失効を保証しません。実プロトコルアダプターと保護された監督サービスを実装・検証するまで開始ゲートを解除しません。

## 回復と画面終了
旧セッションの記録は起動ID・実行ファイル・検索環境の同一性が不足するため、`ended`応答や`not found`だけで削除しません。記録を消して問題を解決したことにせず、承認済みの対象環境で実プロセス・通信の終了を確認してください。停止未確認のまま画面を閉じる操作は、接続停止を意味せず、回復記録を保持します。

## ローカル検証
Python 3.11以上とTkinterを使用します。追加Python依存は不要です。

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
python3 -m compileall -q src tests
```

Windows PowerShellの場合：
```powershell
$env:PYTHONPATH = 'src'
py -3 -m unittest discover -s tests -v
```

テストは模擬Uptermまたはモックを使い、公開中継・実PC・TCPポート22へ接続しません。模擬ライフサイクルのテストだけはリリースゲートをモックして内部の回復コードを確認します。これは実接続の安全性を実証するテストではありません。

## GUI・ビルド
`python src/rescue_host.py` はGUIを開きます。保存された旧セッションがあると回復処理を実行するため、本番PCでは承認前に実行しないでください。

`build_windows.ps1` はWindows x64向けの未検証ビルドスクリプトです。実行するとインターネットからUpterm/PyInstallerを取得します。この作業では実行していません。固定版はv0.39.0。`-UseLocalUpterm` では独立に確認した`-LocalUptermSha256`とライセンスを必須にしました。ダウンロードと同じ経路で取得するチェックサムだけでは配布元侵害を防げません。Pythonビルド依存の完全なハッシュ固定・再現ビルドは未実装です。

## 保証しないこと
- TCP宛先限定、ゲストの権限制限、タイムアウト時の確実な切断・再接続拒否
- Windows ACL/Job Object、実Upterm、実GUI、EXE、スリープ・再起動の動作
- 既にPowerShellで行われた変更・取得された認証情報の取り消し

Uptermの公開鍵認証はOS上の最小権限化ではありません。旧SSH転送モードはPowerShellも起動するため、内側のsshd認証だけを頼りにできません。`authorized_keys`の`permitopen`等もUptermでは強制されません。
