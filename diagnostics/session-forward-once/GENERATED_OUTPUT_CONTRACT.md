## Lifecycle and limits

The initial/pre-build boundary requires the generated directory to be absent.
Only an exit0/output-verified product-build command checkpoint enables the
post-build contract; then all four files are mandatory and exact. Failed/partial
or uncertain builds remain blocked, preserve their outputs, and are not repaired
or retried. Missing output after a cached successful build is rejected, never
synthesized. Presence alone does not prove this invocation created the files or
that the build script ran.

Before Cargo and after it, the permissions input subtree is enumerated directly,
independently of Git ignores. Only its two tracked TOMLs and the four supported
outputs are allowed. Ordinary in-checkout ancestor directories and regular,
single-link generated files are required; generated symlink/junction/reparse,
extra/partial/content uncertainty rejects. The two tracked TOMLs retain their
existing exact blob/is_file/is_symlink checks. Checks are sequential observations, not an atomic filesystem
lease against a concurrent adversarial writer. No rights or settings are changed.

## Bounded evidence

Actual checkout predicates and identity boundary/hash/comparison/write catch sites
record only closed enums. First stage rejection and final-identity rejection are
kept separately in a <=512-byte private checkpoint; the existing outcome contains
only the validated enums/validity boolean. No raw error, path, listing, command,
type name or environment data is published. Unknown/missing/malformed/conflicting
evidence cannot authorize continuation. Original supervisor facts and valid
siblings remain separate; the existing20-file/65536-byte public record cap holds.
